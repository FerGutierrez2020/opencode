3. THE GIT/GITHUB WORKFLOW IN ONE SENTENCE
--------------------------------------------------
   edit files -> git status (review) -> git add (stage)
   -> git commit -m (record) -> git push (send to GitHub)

Every task in this session followed that cycle. Always check
`git status` BEFORE committing, so you only stage the files you intend.

--------------------------------------------------
4. TASK 1 - CHECK THE REPOSITORY STATE
--------------------------------------------------
Command:
  git status

Result:
  On branch master
  Your branch is up to date with 'origin/master'.
  nothing to commit, working tree clean

Explanation:
  - "On branch master"          -> we are on the default branch.
  - "up to date with origin"    -> local and remote are synchronized.
  - "nothing to commit"         -> no modified/staged files.
  - "working tree clean"        -> no untracked files.

Useful variants:
  git status                 # full status
  git status --short         # compact output (-s)
  git remote -v              # show the remote URL(s) of the repo
  git log --oneline -10      # show the last 10 commits (one line each)

8. TASK 5 - GENERATE AN IMAGE FROM A TEXT FILE
--------------------------------------------------
Goal : turn the TXT file (opencode-slash-commands.txt) into a picture
       (PNG), so the reference can be shared as an image.

Step 8.1 - Check which tools are installed on the system
  which convert magick python3 pandoc wkhtmltoimage
  python3 -c "import PIL; print('PIL ok')"
  Result: "convert" (ImageMagick) and Python + PIL are available.

Step 8.2 - Choose a monospaced font that exists on the system
  fc-list | grep -iE "mono|dejavu-sans-mono|liberation"
  Result example: DejaVu Sans Mono -> /usr/share/fonts/truetype/
                  dejavu/DejaVuSansMono.ttf  (+ a Bold variant)

Step 8.3 - Write a Python script with Pillow
  The script (render_slash.py, run from /tmp/opencode/):
    - reads the TXT file line by line,
    - wraps long lines so nothing is cut off,
    - draws a dark "terminal window" background with a title bar,
    - prints each line in a monospaced font,
    - colors sections (yellow headings), commands (cyan),
      usage/keybinds (green) and command names (magenta),
    - saves the result as opencode-slash-commands.png.

  Key Pillow concepts used (good to study):
    from PIL import Image, ImageDraw, ImageFont
    Image.new("RGB", (width, height), color)   # blank canvas
    ImageDraw.Draw(image)                      # drawing context
    ImageFont.truetype(path, size)             # load a font
    draw.rectangle(...) / draw.ellipse(...)    # shapes
    draw.text((x, y), text, font=..., fill=...) # text

Step 8.4 - Run the script
  python3 /tmp/opencode/render_slash.py
  Output:
    saved .../opencode-slash-commands.png 1038x6295

13. GIT CHEAT-SHEET USED IN THIS SESSION
--------------------------------------------------
  git status                  # see current state
  git status --short          # compact state
  git remote -v               # show remote repository URL
  git log --oneline           # list commits (short)
  git log --oneline --reverse # list commits from oldest to newest
  git show <commit>           # inspect one commit in detail
  git show <commit> --stat    # only which files changed
  git diff                    # see pending changes (unstaged)
  git add <file>              # stage a file
  git add .                   # stage all changes (use with care)
  git commit -m "message"     # commit staged changes
  git push                    # upload commits to the remote
  git branch -M main          # rename the branch to "main"

Command chains (allowed and useful):
  git add file && git commit -m "msg" && git push
  # && runs the next command only if the previous one succeeded.
  # If the commit fails (e.g. missing message), the push is NOT run.

--------------------------------------------------
14. GOOD PRACTICES FOR STUDENTS
--------------------------------------------------
1. Commit small, logical units - one feature per commit.
2. Write clear commit messages that explain WHAT and WHY.
3. Always run `git status` before `git add` and review with `git diff`.
4. Do not commit secrets: API keys, tokens, passwords. Use a .gitignore
   file (e.g. ignore .env, node_modules/, dist/).
5. Use a README to explain the project and a .gitignore to protect it.
6. Only push when you are sure the changes are correct.
7. Keep documentation consistent: same language, same style, same
   structure across files.
8. Test your scripts before committing them (here: run the generator
   and check the PNG is created before pushing it).

--------------------------------------------------
15. TROUBLESHOOTING TIPS
--------------------------------------------------
Problem: "git push" asks for credentials.
  -> Authenticate once: install GitHub CLI (`gh auth login`) or use a
     Personal Access Token / SSH key (see setup guide in the repo).

Problem: "nothing to commit, working tree clean" but you wrote a file.
  -> The file might be ignored (check .gitignore) or you edited it
     OUTSIDE the repository folder. Run `ls` and `git status --short`.

Problem: commit succeeded but you cannot see it on GitHub.
  -> Run `git push` again and check output; the branch must be uploaded:
     `git push -u origin master`.

Problem: text was cut in the generated image.
  -> Increase the line wrapping width in the Python script (MAXW) or
     reduce the font size.

Problem: the image does not render in the README on GitHub.
  -> The image must exist in the repository and the path in the
     markdown `![alt](path)` must match exactly (case-sensitive).
